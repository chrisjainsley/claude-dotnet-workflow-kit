# None

No tracker is configured. The user's own description of the work, given in chat or
pasted from wherever they keep it, is the ticket: it stands in for title, acceptance
criteria and repro steps, and there is no separate parent or linked item to fetch.

## Fetch a ticket

There is nothing to fetch. Read the user's description as the full brief. If it does
not include acceptance criteria, ask for them before writing the plan; do not invent
criteria to fill a section.

## Start work

There is no work item to assign or transition. A branch is still created and pushed
the normal way; skip any tracker-specific step.

## Context for the plan

There is no parent feature, sibling story or attachment to pull. The plan's Context
section is built entirely from what the user said and from the code itself.

## Post the QA report

Nothing is posted anywhere. The QA report still gets written, since it is useful to
the user, but it stays in the review artifact and in chat; there is no destination to
send it to and no state to avoid changing.
